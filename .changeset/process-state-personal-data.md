Personal data in a process's state. `Process.StateArgs` gains `personal` and `person`, as an event's payload has them: every lifecycle event that carries the state stores the marked fields encrypted with the key of the person the state names, by its field marked `person()` or the instance's id, and sets the event's `person`. Once that person is forgotten the fields read as `null` and the instance carries on to its end; the handlers see them as `T | null` and the schema takes `null` for them, so a handler may clear one itself. A state starts naming nobody, so its `personal()` and `person()` fields default to `null`; it names nobody while its `person` field is empty, or, without one, while it holds no personal value, and a step that sets a personal field with nobody named fails with `ValidationError`. An app whose state starts with personal data, or marks two `person()` fields, does not start. The export lists the lifecycle events that name the person with the personal fields of their state, a step of an instance whose state names a restricted person is refused with `ProcessingRestrictedError` before its handler runs and retried once the restriction lifts, the store appends a lifecycle event only while each person the instance was loaded with still holds the key it was opened under, and a failed step's dead letter is sealed under the person its event names, or else the one the state names, a deadline's included.
