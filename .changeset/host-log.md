Requests refused before the app serves them are audited in a host log, apart from the access log: one record per refusal, `{ at, tenant, reason, target, actor }` (`HostRejection`), with a reason from a closed set (`HostRejectionReason`): `no-route`, `method-not-allowed`, `payload-too-large` and `invalid-json` from the Worker of `createWorker`; `tenant-unresolved` and `actor-unresolved` when the host's tenant or actor function throws or names nothing; `actor-invalid` when `as` refuses the actor it named; `unknown-command` and `unknown-query` from the Durable Object; `tenant-forgotten` and `tenant-frozen` from the app itself, on every host. Ids and names alone: the route's pattern, never its path, body, headers or the error's message, and no actor once it was refused. `app/audit.ts` now exports `onHostRejection` (`OnHostRejection`) beside `onPersonalDataAccess`, and the app refuses to start without it; without `app/audit.ts` the records go to the host's logger at `info` as `request refused`. The refusal waits for the record and fails with what `onHostRejection` throws. `createBounda` in `@bounda-dev/react-router` and `@bounda-dev/react-router/cloudflare`, and `createWorker`, take the `registry` whose `app/audit.ts` receives it, which the `bounda()` Vite plugin and the `create-bounda` Worker pass; `createTestApp` takes `onHostRejection`; `app.tenant` (`BoundaApp`) names the tenant the app serves; `hostLogOf` records for a host of your own. The inventory lists the host log (`host-log`) beside the access log. The Worker now names a request's tenant and actor before it reads its body, so those refusals carry them. A Durable Object started on a forgotten tenant now refuses every command and query with `TENANT_FORGOTTEN`, where it answered `NOT_FOUND`; React Router's Cloudflare host refuses an empty tenant name, as its Node host does.
