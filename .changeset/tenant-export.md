Hand a tenant's data back to its controller, as article 28(3)(g) of the GDPR asks of a processor at the end of its service, before `forgetTenant` deletes it or instead of it. `exportTenant(tenant)`, on every client, streams every person (restrictions, recipients, categories held), every event up to the head, every scheduled command, dead letter, subscriber failure, remembered answer, read-model row and forget-ledger entry, every value opened and nothing held back, a page at a time, with the app's categories and the ports that return each one's data in its header, and ends with the count of each kind; it fails with `ConcurrencyError` when the stream moves while it reads, and is recorded in the access log as `exportTenant`. `tenantExportJsonLines` writes it as JSON Lines, `readTenantExport` reads it back and checks it is whole. A Durable Object streams it over RPC and `connect` types it; `tenantExportResponse` from `@bounda-dev/react-router` answers a route with the file; `bounda export-tenant <tenant> [--output <file>]` writes it and `bounda check-tenant-export <file>` checks it. Adapters gain `Scheduler.scan`, `DeadLetterStore.scan`, `PersonStore.scan` and `PersonalKeyStore.persons`, which page every record by a key no write changes, and `RecipientStore.disclosuresOfMany`, the disclosures of a page of persons in one read, and `ListAllIdempotencyRecordsArgs.after` may be given as `undefined`, read as absent; the in-memory stores page by code point, as the SQL stores do. PostgreSQL's storage gains migration 12, the indexes that compare those keys, and the remembered answers' keys, by bytes, so each page is read through an index rather than a sort of the whole table.
