Personal data in read models, and a log of who opened whose. A read model's view marks the column that holds the id of the person a row is about with `.person()`, a string and at most one per read model, and the columns that hold their data with `.personal()`; the adapters store them as before. `exportPersonalData` gains `readModels`: for every read model with a person field, the rows that name the person, each with its primary key as `key` and its personal fields as `data` (`ExportedRow`), read through the read model's own storage. `.bounda/types.ts` now checks every read model: one with personal fields needs a person field and a projection of `PersonalDataForgotten`, and none may mark two person fields; the app refuses the same at start with `ConfigurationError`. Every operation that hands out personal data in the clear is recorded once per call, never sampled: `exportPersonalData`, `deadLetters.list`, `get`, `retry` and `discard`, and every query of a read model with personal fields, naming the persons of the rows it read. A record (`PersonalDataAccess`) is `{ operation, actor, persons, personCount, at, detail }`, with at most `MAX_ACCESS_PERSONS` persons. It goes to `onPersonalDataAccess` from an optional `app/audit.ts`, which the generator puts in the registry as `audit`, so every host gets it, or to the app's logger at `info` as `personal data accessed` without one; `createTestApp` never calls it, and takes `onPersonalDataAccess` for a test that wants the records. The hook runs before the data is handed out, and before a letter is retried or discarded; when it throws, the call rejects with its error and hands nothing out.
